# DDD ワークフローのコード例

会議室予約と利用資格判定を題材にした Rust・TypeScript の実装例です。実プロバイダで生成したコードを、ユーザーの指示に従って直接修正し、両方を Event Sourcing に統一しています。

| 言語 | コード・条件・検証結果 | テストの実行 |
|---|---|---|
| TypeScript | [TypeScript 版](ddd-typescript-default/README.md) | 対象ディレクトリで `node --test` |
| Rust | [Rust 版](ddd-rust-default/README.md) | 対象ディレクトリで `cargo test` |

予約ID・会員ID・会議室IDの値域は1以上の整数です。DP の `parse` は域外入力を操作固有のエラーで返し、`of` は同じ検証を通して、域外なら panic／throw します。

各例は、[ファクトリの命名規約](../ja/facets/knowledge/ddd-modeling.md#ファクトリ名の選択)に従います。VO の `of` と型付き入力の `parse`、Entity の業務名による生成、ES の `replay` を使い分けています。自前の静的／関連ファクトリを検査する `factory-naming` も含め、両言語の DDD lint を確認しています。

リポジトリの読み込みは `Result<Reservation | undefined, RepositoryError>`、保存は `Result<void, RepositoryError>` を返します。Rust はそれぞれ `Option<Reservation>`、`()` を成功値にします。保存は `store(event, snapshot)` で、コマンドが生んだドメインイベントと、その直後の集約（スナップショット）を受け取ります。集約IDはイベントが持つので、別の引数では渡しません。集約とイベントはシーケンス番号を持ちます。読み込みは最新のスナップショットに、その番号より後のイベントだけを `replay` で適用します。全履歴を毎回再生すると、イベント列が長くなるほど読み込みが遅くなるためです。インメモリ実装は、イベント列と集約そのもののスナップショットを保持し、スナップショットを生成時と指定した件数ごとに更新します。公開するのはポートとコンストラクタだけで、テストは `findById` を通して確かめます。ユースケースは集約の操作と保存依頼を行います。

## 生成と直接修正の記録

基本コンストラクタも、[合意した制約](../ja/facets/policies/ddd-domain-layer.md#基本コンストラクタと補助の生成経路)に揃えています。TS の唯一の private constructor と、Rust の非公開の new へ、検証付きの補助経路が委譲します。基本経路の複数定義、迂回、委譲の循環を linter が拒否します。

元の生成は TAKT 0.67.0 と Codex のプロファイルで TypeScript、Rust の順に実行しました。元の業務要件・パッケージ配置は各版の `task.txt`、設定は `runtime.yaml` と `config.yaml` に保存しています。

その後、保存用の余分な型を廃止して両言語を ES に統一する指示を受け、生成済みコードを直接編集しました。集約・ポート・保存実装・宣言・テストを更新し、後方互換の別名や保存経路を削除しています。

2026-10-05 には、リポジトリの形を `store(event, snapshot)` とスナップショット＋差分の読み込みに直す指示を受け、同じく直接編集しました。`store` の集約ID引数と、テスト用に公開していた `eventsFor`／`events_for` を削除し、全履歴を再生する `restore` を `replay(events, snapshot)` に置き換えています。

`generation.json` の `original_generation` に元の生成記録、`manual_revision` と `standalone_verification` に直接修正と検証結果、`current_source_file_sha256` に現在のソースのハッシュを記録しています。テスト、TS の型検査、Rust の整形、両言語の DDD lint は修正後のコードで確認しました。

現在の例は、継続的なチェックでテスト・型検査または整形・現行のドメイン検査を実行します。元の生成と過去の検証結果は `generation.json` の履歴に残します。インストーラが利用者のプロジェクトへ導入するのは言語別のバンドルと検査ツールです。

## 利用資格の例

2026-10-09に、独立した利用組織と利用者から利用資格を判定する例を両言語へ追加しました。予約とは別のコンテキストとして宣言し、二つの集約と判定サービスを `access` モジュールにまとめています。

サービスは各集約の判断を組み合わせ、状態や呼び出し履歴を保持せず、取得・保存・通信を行いません。所属判断は利用者から組織自身の識別子照合へ委ねます。入力準備の生成イベントと、イベントを生まない判定操作を区別し、生成・復元・判定を公開操作から確認できます。

TypeScript版は成功した実タスクのコードを取り込み、パッケージ名と配置を合わせたものです。Rust版も2026-10-10に、空のプロジェクトから成功した実生成結果へ更新しました。型の保証と必須項目の欠落を区別し、生成イベントの初期復元と既存スナップショットへの続きを別の公開操作で扱います。両方の生成記録で、元の生成、今回の追加の由来、現在の検証結果を区別します。
