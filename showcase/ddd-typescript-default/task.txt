Create a TypeScript workspace (no build step; Node 24 runs the .ts sources directly) for meeting-room reservations with three business packages: a domain package `@acme/reservation-domain` under `packages/command/reservation-domain`, a use-case package `@acme/reservation-use-case` under `packages/command/reservation-use-case`, and an interface-adapter package `@acme/reservation-interface-adapter` under `packages/command/reservation-interface-adapter`. The domain models one reservation aggregate: a member reserves a room for a time slot, and the slot must end after it starts; a confirmed reservation can be cancelled once, and cancelling a cancelled reservation fails. The use-case package declares the port for storing and loading reservations, and a use case that cancels a reservation by its ID and fails when no reservation has that ID. The interface-adapter package implements the port in memory. Write unit tests for the aggregate, and tests for the use case running against the in-memory implementation, with the built-in `node:test` runner outside `src`; they must pass with `node --test` run from the repository root.

One supporting infrastructure package may be added for shared technical types. Keep the meeting-room behavior in the three named business packages.
