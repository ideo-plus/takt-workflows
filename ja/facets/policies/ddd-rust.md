# DDD Rust ポリシー

ほかの DDD ポリシーの規則を Rust のコードでどう判定するかと、Rust だけの規則（その場での変更）を定める。読み替えた結果が規則に反すれば、その規則の判定になる。モジュール配置はモジュール配置ポリシーが持つ。

`from` は固有の関連関数でも `From<T>` の実装でも、失敗しない変換として `Self` を返す。失敗する変換は `try_from`／`TryFrom<T>` で `Result<Self, ConversionError>` を返す。DP の基本入力の検証には既存の `of`／`parse` を使い、変換を追加しても初期化の検証経路を迂回しない。

| 規則（ポリシー） | Rust での判定 |
|------------------|----------------|
| 状態を公開しない（ドメイン層） | `pub`、`pub(crate)`、`pub(super)`、`pub(in …)` のフィールドは公開とみなす |
| 型の外で組み立てない（ドメイン層） | 構造体リテラルと `..` の更新構文は、その型の固有 `impl` の中にだけ書く。`Default` の derive・実装・`Default::default()` による組み立ては、型の外での組み立てとみなす |
| 基本コンストラクタを通す（ドメイン層） | 状態全体を組み立てる非公開の関連関数を1つにする。リテラルとタプル構造体の直接初期化はこの基本経路だけに置く。検証するファクトリは、補助経由を含めてそこへ委譲する。ES の `replay` は値で受け取ったスナップショットを replay メソッドで進めるので、生成経路ではない |
| 状態を変えるのは宣言済みのメソッドだけ（ドメイン層） | `&mut self` を取るメソッドが、状態を変えるメソッドである |
| その場で変えるか、新しいインスタンスにするか（ドメイン層） | その場で変える。下の「その場での変更」に従う。コマンドは `&mut self` を取って集約を変え、`Result<success_type, error_type>` を返す。`&self` や `self` を取ってイベントだけを返すメソッドは、状態を変えないコマンドとみなす |
| 内部可変性で隠さない（ドメイン層） | `Cell`、`RefCell`、`Mutex`、`RwLock`、アトミック型にドメイン型の業務状態を持たせることは、内部可変性で隠すことにあたる。技術的なキャッシュに使うときは、そのことを明記する |
| 業務上の失敗は Result で返す（ドメイン層） | 業務上の失敗を `panic!`、`unwrap`、`expect` で伝えることは throw にあたる。操作のエラー型は `error_type` の名前の enum で、バリアントは写像の case |
| Domain Primitive の初期化 | `pub fn of(value: T) -> Self` と `pub fn parse(value: T) -> Result<Self, Parse…Error>` を必ず置く。`of` は同じ入力の `Self::parse(value).expect(...)` を返す。`parse` は入力依存の拒否ガードで不変条件違反を `Err` にしてから、その入力で初期化する。他の関連関数・復元・複製用の経路から直接初期化しない。`Deserialize` の derive は初期化経路を構文から検査できないため使わず、`parse` を通す実装を置く |
| 検証した入力と初期化する値を揃える（ドメイン層） | 検証後の型変換も、数値が変わらず保持型に収まると確認できれば認める。検証前の変換、丸め、値の変更は REJECT。検査が対応する形式は Rust 知識の「検証後の数値変換」に従う |
| エラー型を広げない（ドメイン層） | `Other(String)`、`Unknown` のような何でも入るバリアントは、広げたことにあたる |
| 壊れた状態の扱い（ドメイン層） | 復元は専用の復元エラーを返すか panic してよい |
| 重複成功（ドメイン層の冪等性） | 成功値を `Applied(イベント)` と `Duplicate` の enum にし、重複のときは `Duplicate` を返す |
| ポートを通す（層の依存） | ポートは trait にする。静的ディスパッチを既定にし、動的ディスパッチは実行時に選ぶ必要があるときだけ使う |
| リポジトリポートの書き込み（インターフェイスアダプタ層） | 保存先を変えるメソッド（`store`、`delete_by_id`）は既定で `&mut self` を取る。`&self` を取って実装が `RefCell` などで保存先を変えるのは、内部可変性で変更を隠すことにあたる。並行処理でポートを共有してロックが必要なときだけ、trait に `Send + Sync` を付けて `&self` を取り、実装は `Mutex` や `RwLock` で保存先を守る |

## その場での変更

Rust では、変えるものを `&mut` で受け取り、その場で変える。集約だけでなく、値オブジェクト、Domain Primitive、Entity、コレクションも同じである。借用検査が変更中の排他を保証し、`&` で共有された値は変わらないので、値の意味は所有権が守る。変える前の値が要るときは、呼び出し側が `clone` してから変える。

| 基準 | 判定 |
|------|------|
| `&self` や `self` を取り、自分の型の新しいインスタンス（`Self`、`Result<Self, E>`、`Option<Self>`）を返すメソッドがある | REJECT。`&mut self` を取ってその場で変える。戻り値は `()`、失敗し得るなら `Result<(), E>` |
| 値で受け取った引数を変更後の複製として返すメソッドがある（`fn add_to(&self, total: Money) -> Money`） | REJECT。変更する値自身を受け手とし、`&mut self` で変更する |
| 外部の可変参照引数を変更するメソッドがある（`fn add_to(&self, total: &mut Money)`） | REJECT。変わる値自身を `&mut self` で変更する。この規則は構文を判定するもので、引数を実際に変更する文までは証明しない |
| ドメインの型が `Add`、`Sub`、`Mul`、`Div`、`Rem` を実装している | REJECT。新しい値を返す演算子ではなく、`AddAssign` などのその場で変える演算子を実装する |
| `&self` を取る問い合わせが、自分とは別の型の値（合計、表示や永続化のための複製）を返す | OK |
