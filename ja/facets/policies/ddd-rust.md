# DDD Rust ポリシー

DDD の層の規則を、Rust 固有の可視性、組み立て、変更、エラーの仕組みで適用する。

## 原則

| 原則 | 基準 |
|------|------|
| 既定は非公開 | ドメインの構造体のフィールドは非公開にし、必要な操作だけを公開する |
| 組み立ては一か所 | ドメイン型の構造体リテラルと更新構文は、その型の `impl` の中にだけ書く |
| `&mut self` はコマンド | `&mut self` を取るメソッドは、宣言済みコマンドか宣言済みの replay メソッドである |
| 操作ごとに 1 つのエラー enum | 写像された各操作は、自分の enum を `E` とする `Result<_, E>` を返す |
| 静的ディスパッチを優先 | ポートは trait にし、動的ディスパッチは必要なときだけ選ぶ |

## 可視性と組み立て

| 基準 | 判定 |
|------|------|
| ドメインの構造体のフィールドが `pub`、`pub(crate)`、`pub(super)` | REJECT |
| ドメイン型の構造体リテラルや `..` の更新構文が、その型の固有 `impl` の外にある | REJECT |
| 集約や Entity が `Default` を derive または実装している、または `Default::default()` で組み立てている | REJECT |
| 状態全体を受け取るコンストラクタが公開されていて、検証を飛ばしている | REJECT。非公開にし、検証するファクトリから呼ぶ |
| 状態全体を検証する `restore` 関連関数で復元する | OK |

## 変更

| 基準 | 判定 |
|------|------|
| `&mut self` のメソッドが、宣言済みコマンドにも宣言済みの replay メソッドにも写像されていない | REJECT |
| `Cell`、`RefCell`、`Mutex`、`RwLock`、アトミック型がドメイン型の業務状態を持っている | REJECT。技術的なキャッシュにだけ使い、そのことを明記する |
| 値オブジェクトや Domain Primitive に `&mut self` のメソッドがある | REJECT |

## エラー

| 基準 | 判定 |
|------|------|
| 写像された操作が、`error_type` で名付けた enum を `E` とする `Result<_, E>` を返し、バリアントが写像された case と一致する | OK |
| エラー enum が業務上の失敗のための何でも入るバリアント（`Other(String)`、`Unknown`）を持つ | REJECT |
| 業務上の失敗を `panic!`、`unwrap`、`expect` で伝えている | REJECT |
| 壊れた状態や履歴の復元が、専用の復元エラーを返す、または panic する | OK。業務上の失敗ではない |

## モジュール

| 基準 | 判定 |
|------|------|
| `file` 配置で、子を持つモジュールが `mod.rs` を使っている | REJECT。`<m>/` の隣に `<m>.rs` を置く |
| `mod-rs` 配置で、子を持つモジュールが `<m>.rs` になっている | REJECT。`<m>/mod.rs` を使う。葉は `<leaf>.rs` のまま |
| 選んだ配置から逃れるために `#[path]` 属性を使っている | REJECT |
