# DDD インターフェイスアダプタポリシー

ポートは責務で名付け、リポジトリは 1 つの集約に限り、復元はドメイン自身のファクトリで行い、コマンド側とクエリ側を分ける。

## 原則

| 原則 | 基準 |
|------|------|
| 責務でポートを名付ける | ポートは内側の層が必要とするものの名前にし、背後の技術の名前にしない |
| 1 リポジトリに 1 集約 | リポジトリは 1 種類の集約を保存し、読み込む |
| ドメインを通して復元する | アダプタは集約をドメインの restore ファクトリでだけ組み立て直す |
| 安全な永続化 | 保存は状態を安全に再永続化するか、不変の履歴へ追記する |
| 両側を分ける | コマンド側とクエリ側は互いに依存しない |
| クライアントはここに置く | データベースと RPC のクライアントはこの層に置く |

## ポートとリポジトリ

| 基準 | 判定 |
|------|------|
| リポジトリポートが `<Aggregate>Repository` という名前でない、または名前に保存媒体（`Postgres`、`Dynamo`、`InMemory`、`Http` など）を含む | REJECT |
| リポジトリの実装が媒体名の接頭辞を持ち、ポート名で終わる（`PostgresInvoiceRepository`） | OK |
| 理由なく、リポジトリポートに基本の動詞 `find_by_id`、`store`、`delete_by_id`（言語の表記に合わせる）がない | REJECT |
| リポジトリポートが画面向けの検索を提供している | REJECT。クエリ側に置く |
| 1 つのリポジトリが複数種類の集約を扱っている | REJECT |
| 層構造でポートを `repository`、`external-client`、`es-infrastructure` のいずれにも分類していない | REJECT |
| 内側の層で宣言したポートをこの層で実装し、composition root で結線する | OK |
| 採用するか変換するかを明示せずに、外部のモデルをドメインの中で使っている | REJECT |

## 復元と永続化

| 基準 | 判定 |
|------|------|
| アダプタがドメインのオブジェクトを、リテラル、`new`、キャスト、既定値、restore ファクトリ以外のコンストラクタで組み立てている | REJECT |
| 保存データを検証せずにドメインのオブジェクトへ写している | REJECT |
| 同時更新があり得るのに、`store` が無条件に上書きしている | REJECT。期待バージョンや同等の制約を使う |
| イベントソーシングの永続化が既存のイベントを書き換える、または消している | REJECT |
| 一意性を、保存先の制約ではなく先に読んで確かめることで決めている | REJECT |
| データベース固有のエラーを変換せずにユースケース層へ漏らしている | REJECT |

## コマンド側とクエリ側

| 基準 | 判定 |
|------|------|
| コマンド側のパッケージがクエリ側のパッケージに依存している、またはその逆 | REJECT |
| クエリ側のコードがドメインの型やリポジトリポートを import している | REJECT。DAO と DTO を使う |
| 読み取りモデル更新器（RMU）が両側に依存する | OK |
| 読み取りモデル更新器が、番号の比較だけで欠番や重複を無視している | REJECT。イベント ID、集約内の番号、配送側の番号を区別する |
| 読み取りモデルの反映遅延を、それに依存する呼び出し側から隠している | REJECT。遅延を明示する |

## アダプタのテスト

| 基準 | 判定 |
|------|------|
| ポートの契約をテストするインメモリ実装がない | 警告 |
| ポートの契約テストが成功しか扱っていない | REJECT。競合と失敗も扱う |
