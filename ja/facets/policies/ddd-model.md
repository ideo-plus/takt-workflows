# DDD モデルポリシー

ドメインモデル宣言を業務概念の唯一の定義として保ち、計画・コード・レビューはそれを再定義せず安定 ID で参照する。

## 原則

| 原則 | 基準 |
|------|------|
| 唯一の定義元 | 集約、要素、不変条件、コマンド、ファクトリ規則、イベント、エラー、状態はドメインモデル宣言だけで定義する |
| モデルが先、コードが後 | 業務の振る舞いを追加・変更する変更は、先に宣言を更新し、コードはそれに従う |
| 集約は不変条件を持つ | 不変条件を持たない集約は集約境界ではない |
| 操作はエラーを持つ | 各コマンドと各ファクトリ規則は自分のドメインエラーを宣言し、操作間で共有しない |
| 安定した識別 | 要素 ID は変えない。改名は name だけを変える |
| 参照し、再定義しない | 写像、計画、コード、レビューはモデル ID を引用する |
| 写像がモデルを覆う | モデルの全集約・全操作・全エラーが集約写像にコード上の位置を持つ |

## ドメインモデル宣言

| 基準 | 判定 |
|------|------|
| 宣言にない業務操作、ドメインエラー、不変条件、状態、イベントをコードが追加している | REJECT。先にモデルへ宣言する |
| 不変条件を持たない集約がある | REJECT。候補を統合するか格下げする |
| コマンドが状態効果（`transitions` か `none`）を宣言していない、または宣言と遷移が食い違う | REJECT |
| コマンドやファクトリ規則にドメインエラーがない、または別の操作が所有するエラーを指している | REJECT |
| コマンドがイベントを宣言していない、2 つ以上宣言している（`events: [...]`）、またはその `event` を別のコマンドが生む | REJECT。コマンドが生むイベントはちょうど 1 つ（`event: <イベント ID>`） |
| `effect: accumulation` のコマンドに `command-id-memory` の冪等性戦略がない | REJECT |
| 要素 ID を改名した、廃止後に再利用した、または `<kind>.<segments>` の形式に従っていない | REJECT |
| 分割・統合・廃止が `lineage` に記録されていない | REJECT |
| 他の集約を ID で参照せず埋め込んでいる | REJECT |
| モデルがモジュール、パッケージ、ポート、リポジトリ、ユースケースの手順を決めている | REJECT。それらは写像とコードの責務 |

## 集約写像

| 基準 | 判定 |
|------|------|
| モデルの集約に写像の行がない | REJECT |
| 集約が `programming_model`（`actor` か `class`）と `persistence_method`（`state-sourcing` か `event-sourcing`）を宣言していない | REJECT |
| コマンドやファクトリ規則に写像されたメソッドとエラー型がない、コマンドに写像された `success_type` がない、またはドメインエラーに写像された case がない | REJECT |
| イベントソーシングの集約が `replay_methods` にないメソッドでイベントを適用している | REJECT |
| 写像の行が ID を引用せず要素を再定義している | REJECT |
| ドメインコードを置くパッケージやモジュールが `domain_packages` にない、またはその親の階層がない | REJECT |
| `domain_packages` の項目に業務用語、モデル参照、根拠のいずれかがない | REJECT |

## モデルとコードの一致

| 基準 | 判定 |
|------|------|
| コードが操作、エラー、replay メソッドを写像どおりの名前で実装している | OK |
| コードと写像が食い違い、写像を更新せずにコードだけを変えている | REJECT |
| 正しいコードを書くのを妨げるモデルの欠落を見つけた | 欠けている宣言を記録する。コードで作り出さない |
| モデルとプロジェクトの明示的な方針が衝突する | どちらも黙って上書きしない。衝突、範囲、解決を記録する |
