# DDD ドメイン層ポリシー

ドメインモデルを常に有効に保つ。状態は隠し、完全コンストラクタでだけ組み立て、宣言済みコマンドでだけ変え、業務上の失敗は操作ごとの値として返す。

## 原則

| 原則 | 基準 |
|------|------|
| 常に有効 | 存在するオブジェクトは不変条件を満たす。不正な状態を作らず、露出もしない |
| 入口は一つ | 集約と Entity は、状態全体を受け取る完全コンストラクタでだけ組み立てる |
| 状態を変えるのはコマンド | 宣言済みコマンドのメソッドか、宣言済みの replay メソッドだけが状態を変える |
| 尋ねずに頼む | 業務判断はデータを持つオブジェクトの中で行い、getter で読み出して判断しない |
| 失敗は値 | 想定された業務上の失敗は、その操作固有のエラー型を持つ Result で返す |
| 途中の変更を残さない | 拒否された操作は状態をそのまま残す |
| 状態を所有する | 可変な入力は複製して持ち、状態を参照のまま外に渡さない |

## 組み立てと復元

| 基準 | 判定 |
|------|------|
| ドメインの状態が公開フィールドで外から読み書きできる | REJECT |
| 集約や Entity をその型の外で、リテラル、既定値、キャスト、公開コンストラクタで組み立てている | REJECT |
| ファクトリが入力を検証する前にインスタンスを作る、または空のインスタンスを作って後から埋める | REJECT |
| `init`、`setup`、`initialize`、`reset`、`configure` のメソッドで組み立てを完了させている | REJECT |
| 永続化された状態を、状態全体を検証せずに組み立て直している | REJECT。状態全体を検証して完全コンストラクタで組み立てる restore ファクトリを通す |
| restore ファクトリが壊れた状態を throw で拒否する | OK。壊れた状態は業務上の失敗ではない |
| 写像が操作に結び付けたファクトリが、宣言済みのエラーがあるのに値そのものを返している | REJECT |

## 状態の変更

| 基準 | 判定 |
|------|------|
| 状態を変えるメソッドが、宣言済みコマンドに写像されたメソッドではない | REJECT |
| 集約や Entity に setter や汎用の更新メソッドがある | REJECT |
| 名前（`apply`、`on_event` など）だけを根拠に replay メソッドとして扱っている | REJECT。replay はイベントソーシングの集約の `replay_methods` に宣言されたメソッドだけ |
| 集約や Entity がコマンドの中で状態を変える | 言語ポリシーが決める。Rust は、借用検査で排他が保証される `&mut self` で変える。TypeScript は、参照が自由に共有されるので新しいインスタンスを返す |
| 値オブジェクトや Domain Primitive が組み立て後に変わる | REJECT |
| 内部可変性や共有参照で業務上の状態変更を隠している | REJECT |
| replay が新しい業務判断をする、または保存済みイベントを業務上の失敗として拒否する | REJECT。replay は事実を適用するだけ。壊れた履歴は復元を中止する |

## getter と判断

| 基準 | 判定 |
|------|------|
| ドメインコードが別のドメインオブジェクトの状態を getter で読んで判断している | REJECT。そのオブジェクトに処理を頼む |
| ドメインの状態に対する比較や計算を、所有するオブジェクトの外で行っている | REJECT |
| 表示や永続化のために、問い合わせメソッドが複製か読み取り専用の値を返す | OK |

## 業務上の失敗

業務上の失敗は操作の契約の一部である。業務ルール違反で例外を投げるという一般的な指針は、このモデルのドメイン操作には当てはまらない。

| 基準 | 判定 |
|------|------|
| コマンドやファクトリが、想定された業務上の失敗を throw で伝えている | REJECT。Result で返す |
| 操作のエラー型に別の操作の case が含まれる、または文字列、`any`、`unknown`、何でも入るバリアントに広げている | REJECT |
| 1 つのエラー型を複数の操作で共有している | REJECT |
| エラーの case が、写像がその操作に宣言した case と一致しない | REJECT |
| 業務上の失敗を検出する前に状態を変えている | REJECT。先に確かめてから変える |
| 想定外の実行時エラーや壊れた状態を throw や panic で扱う | OK。それらは業務上の失敗ではない |

## 値、Entity、コレクション

| 基準 | 判定 |
|------|------|
| 業務上の意味を持つプリミティブ（金額、識別子、数量）を、裸のプリミティブのままドメインの境界を越えて渡している | REJECT。Domain Primitive で包む |
| 値オブジェクトが同一性で等価を判定している、または Entity が値で等価を判定している | REJECT |
| 不変条件を持つコレクションを、複数の所有者の中で裸のリストとして持っている | REJECT。専用の型にする |
| 集約が他の集約を ID ではなく実体で持っている | REJECT |
| ドメインサービスが状態を持つ、永続化する、または集約が持てる判断をしている | REJECT |

## 所有

| 基準 | 判定 |
|------|------|
| 受け取った可変の配列、マップ、オブジェクトを複製せずに持っている | REJECT |
| 状態として持つ可変のコレクションやオブジェクトをそのまま返している | REJECT。複製か読み取り専用の値を返す |
