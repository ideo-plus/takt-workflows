# DDD インターフェイスアダプタ層ポリシー

インターフェイスアダプタ層のコード（リポジトリの実装、外部とのやり取り、クエリ側、読み取りモデル更新器）を判定する。集約の組み立て直しはドメイン層ポリシー、依存の向きとコマンド側・クエリ側の分離は層の依存ポリシー、ポートの分類はドメインモデルポリシー（層構造）が持つ。

## ポートとリポジトリ

| 基準 | 判定 |
|------|------|
| リポジトリポートの名前が `<Aggregate>Repository` でない、または保存媒体（`Postgres`、`Dynamo`、`InMemory`、`Http` など）を含む | REJECT |
| リポジトリの実装が媒体名の接頭辞を持ち、ポート名で終わる（`PostgresInvoiceRepository`） | OK |
| 理由なく、リポジトリポートに基本の動詞 `find_by_id`、`store`、`delete_by_id`（言語の表記に合わせる）がない | REJECT |
| リポジトリポートのメソッドが `Result` を返さない（`store` が `void` や `()` を返す） | REJECT。読み込みと保存は失敗しうるので、`Result<…, RepositoryError>` を返す。`RepositoryError` はポートの隣に宣言するインフラの失敗であり、業務上のエラーではない |
| 検索が、見つからないことをポートの失敗として返している | REJECT。`undefined`（Rust は `None`）を成功として返し、見つからないことはユースケースが自分のエラーにする |
| リポジトリポートが画面向けの検索を提供している | REJECT。クエリ側に置く |
| 1 つのリポジトリが複数種類の集約を扱っている | REJECT |
| リポジトリの実装が、ポートにない公開メソッドやフィールド（テスト用の `eventsFor` など）を持つ | REJECT。公開するのはポートとコンストラクタだけ。テストはポート（`findById`）を通して確かめる |
| 外部のモデルを、採用するか変換するかを明示せずにドメインの中で使っている | REJECT |

## 永続化

標準は Event Sourcing。イベント履歴は集約IDごとの追記専用の列として保存し、`via: event-replay` を宣言する。リポジトリの公開APIは、集約の読込（`findById`）と、ドメインイベントとその直後の集約（スナップショット）の保存（`store(event, snapshot)`）。読込は最新のスナップショットに、その番号より後のイベントだけを適用し、この再生はアダプタ内部で行う。インメモリ実装も、`Map<Id, readonly DomainEvent[]>`／`HashMap<Id, Vec<DomainEvent>>` にイベントを、`Map<Id, Aggregate>`／`HashMap<Id, Aggregate>` にスナップショットを、そのまま保持する。

| 基準 | 判定 |
|------|------|
| 同時更新があり得るのに、`store` が無条件に上書きしている | REJECT。期待バージョンや同等の制約を使う |
| 要求にない同時更新対策のためだけにバージョン包み型や保存用DTOを追加している | REJECT。必要な並行更新の条件を明示し、余計な型を作らない |
| Event Sourcing の `store` が、集約 ID を別の引数で受け取る、またはスナップショット（イベントの直後の集約）を受け取らない | REJECT。`store(event, snapshot)` にする。イベントが集約 ID を持ち、スナップショットがあれば、読込は最新のスナップショットより後のイベントだけを再生できる |
| 読込が、毎回イベント列の先頭から全履歴を再生している | REJECT。イベント列が長くなるほど読込が遅くなる。最新のスナップショットに、その番号より後のイベントだけを適用する |
| イベントソーシングの永続化が既存のイベントを書き換える、または消している | REJECT |
| 一意性を、保存先の制約ではなく先に読んで確かめることで決めている | REJECT |
| データベース固有のエラーを変換せずにユースケース層へ漏らしている | REJECT |

## 読み取りモデル更新器とクエリ側

| 基準 | 判定 |
|------|------|
| 読み取りモデル更新器が、番号の比較だけで欠番や重複を無視している | REJECT。イベント ID、集約内の番号、配送側の番号を区別する |
| 読み取りモデルの反映遅延を、それに依存する呼び出し側から隠している | REJECT。遅延を明示する |

## アダプタのテスト

| 基準 | 判定 |
|------|------|
| ポートの契約をテストするインメモリ実装がない | 警告 |
| ポートの契約テストが成功しか扱っていない | REJECT。競合と失敗も扱う |
